# Anime video production

Create the video the user requests, not a fixed imitation of a past project. Infer routine choices from the brief and existing assets; ask only for a missing decision that changes the result or for authority the user has not provided. Do not publish or send anything without authorization. Preserve source footage, prompts and user work.

## Workflow

1. **Find the project truth.** Inspect the requested story or source material, existing footage and references, visual direction, desired duration, dialogue, delivery dimensions, available compute and any spending limits. If the user names a generator or runtime, use it. Reuse a suitable project and reference assets rather than restarting. Treat references as appearance/style evidence only unless their pose, framing or motion is also requested; record their source and any attribution or permission uncertainty.
2. **Direct for motion and continuity.** Plan a small number of readable beats. For each shot identify who is present, where they stand, the order and endpoint of each action, weight shifts and follow-through, camera direction, lighting, and what changes at the cut. Give characters stable descriptions and identity references across scenes; transfer only intended attributes from an image. Keep dialogue short enough for the shot, assign a speaker, and specify visible mouth movement and delivery. For Pika H3 Flex read [references/pika-colab.md](references/pika-colab.md) for its prompt structure and practical execution details.
3. **Generate within authorized resources.** Check current model requirements, GPU availability, compute balance/rate, and storage before allocation. When using Colab, reuse one session for related clips when feasible, capture requests and logs, monitor progress and budget, download deliverables, and stop only the task's runtime when finished. Do not purchase credits or silently switch paid providers. If a generation fails, protect already-created work and choose a bounded recovery. Independently generated scenes can drift; a reference improves consistency but does not guarantee it.
4. **Review and edit.** Keep the source scenes and an edit decision list. Inspect clips, especially action, faces, dialogue and cut points; remove repeated gestures and weak continuity where appropriate while preserving requested story beats and speech. Use frame-aligned edits and audio overlaps that do not clip dialogue. For a single source and an EDL of kept frame ranges, `scripts/cut_from_edl.py` performs a non-destructive cut with optional audio crossfades; see [references/finishing.md](references/finishing.md). For complex projects, use the available video workflow or editing tools that best fit the task.
5. **Finish only as requested.** When improving resolution, compare a short AI-upscaled sample against a conventional resize before processing the full video; preserve aspect ratio, original frame rate and audio unless the user requests a change. For mixed audio, do not claim that voice/music can be independently adjusted without usable stems. Time effects away from spoken words, use restrained levels and check peaks. See [references/finishing.md](references/finishing.md).
6. **Verify and deliver.** Probe the actual output for duration, dimensions, frame rate, frame count and audio; decode the entire file. Check dialogue by listening when possible and/or automated transcription, and identify which method was used. Review motion, continuity, transitions, lip sync and the finished soundtrack in playback when tools permit; otherwise say exactly what was sampled and what remains unreviewed. Report the final file, major creative changes, material limitations and actual compute usage if available. Never claim playback, intelligibility, stability or visual quality from metadata alone.

Store prompts, reference provenance, model/revision/seed, submitted graphs, source clips, edit decisions and output verification alongside the project when they exist. Prompted dialogue, actions, frame count and continuity are requests until checked in the output.
